# 🍊 Апельсиновый эквивалент

Telegram-бот для групп: находит явно обозначенные рублёвые суммы и отвечает одним реплаем с эквивалентом в кг апельсинов. Использует заданную вручную цену, по умолчанию 110 ₽/кг. Это самостоятельное приложение; браузерный бот Dwar собирается отдельно.

## Деплой на Ubuntu-сервер

Из **корня репозитория**:

```sh
npm run deploy:orange
```

По умолчанию команда подключается к `root@157.228.143.85` и устанавливает бот в `/var/www/orange-bot`. Нужны локальные Docker с Compose plugin, Bash, SSH, SCP и gzip; в Windows используйте WSL с интеграцией Docker Desktop. На сервере нужны Docker Engine, Compose plugin и `flock` (обычно уже есть в Ubuntu). Для SSH рекомендуется ключ; нестандартный порт и ключ задайте в `~/.ssh/config`. Локальная установка Node.js 24 и зависимостей бота не требуется: сборка выполняется внутри Docker. При деплое отдельные этапы тестирования, typecheck и lint не запускаются. Они выполняются в GitHub Actions или вручную в каталоге приложения. Сама сборка использует TypeScript-компилятор `tsc`, поэтому ошибки типов исходников могут остановить её.

Если установлен Buildx, скрипт собирает образ через него. Если `docker buildx` недоступен, а архитектура локального Docker совпадает с архитектурой сервера, используется обычный `docker build` с `DOCKER_BUILDKIT=0`. При разных архитектурах нужен [Buildx](https://docs.docker.com/build/buildx/) на компьютере запуска деплоя; без него скрипт остановится до сборки и передачи образа. Современный рекомендованный вариант — Buildx; резервный classic builder [объявлен Docker устаревшим](https://docs.docker.com/engine/deprecated/#legacy-builder-fallback).

Перед **первым** деплоем один раз подготовьте сервер, выполняя команды из корня репозитория:

```sh
ssh root@157.228.143.85 'mkdir -p /var/www/orange-bot'
scp orange-telegram-bot/.env.example root@157.228.143.85:/var/www/orange-bot/.env
ssh -t root@157.228.143.85 'chmod 600 /var/www/orange-bot/.env; nano /var/www/orange-bot/.env'
```

В редакторе на сервере заполните `BOT_TOKEN`, при необходимости измените `ORANGE_PRICE_RUB_PER_KG` (по умолчанию 110). Эти команды подготовки не повторяйте при обновлении: SCP перезапишет `.env`. Токен в репозиторий и Docker-образ не попадает. Перед переносом остановите локальный экземпляр бота: два процесса с одним токеном одновременно запускать нельзя. Если нужны прежние настройки чатов, перенесите резервную копию SQLite из локального volume при остановленных экземплярах; первый серверный запуск создаёт отдельную пустую базу.

Затем запустите `npm run deploy:orange`. Скрипт проверит сервер, определит amd64/arm64, соберёт образ с уникальным тегом, сожмёт и передаст его через SSH, загрузит через `docker load` и пересоздаст контейнер без сборки на сервере. SQLite сохраняется в volume `orange-bot_orange-data`, имя проекта Compose всегда `orange-bot`. Серверный `.env` при обновлении не перезаписывается. Доставка прерывается при ошибке сборки или передачи; текущий контейнер до активации остаётся запущенным.

После активации скрипт 15 секунд проверяет, что процесс работает без перезапусков. При ошибке восстанавливает предыдущие образ и Compose-файл, а при неудачном первом запуске останавливает контейнер. Это проверка процесса; доступность Telegram и ответы проверьте командой `/rate`. Обновление подразумевает короткую остановку старого процесса. При параллельном запуске активации защищены серверной блокировкой; команды выполняйте последовательно.

Для ручного отката из корня репозитория:

```sh
npm run rollback:orange
```

Откат восстанавливает предыдущие успешные образ и Compose-файл. База и `.env` сохраняют актуальные значения. Образы автоматически не удаляются: текущий и предыдущий нужны для запуска и отката.

Логи и остановка на сервере:

```sh
ssh root@157.228.143.85
cd /var/www/orange-bot
docker compose -p orange-bot --env-file .release.env logs -f --tail=50
docker compose -p orange-bot --env-file .release.env stop
# Повторный запуск, в том числе после изменения серверного .env:
docker compose -p orange-bot --env-file .release.env up -d --no-build --pull never --force-recreate
```

Для другого подключения или каталога задайте переменные перед командой (либо экспортируйте их в своём shell):

```sh
ORANGE_DEPLOY_SSH=root@157.228.143.85 ORANGE_DEPLOY_DIR=/var/www/orange-bot npm run deploy:orange
```

Такие же переменные поддерживает `npm run rollback:orange`. `ORANGE_DEPLOY_SSH` принимает `user@host` или алиас из `~/.ssh/config`, `ORANGE_DEPLOY_DIR` — абсолютный путь без пробелов и `..`. Для Bash и тестов доставки есть `npm run test:orange-deploy`; реальный сервер эти тесты не используют.

## Запуск на своём компьютере

Установите Docker Desktop (Windows/macOS) либо Docker Engine с Compose plugin (Linux), запустите Docker. Компьютер должен оставаться включённым, без сна, с доступом в интернет. Для автоматического восстановления включите запуск Docker при входе в систему. Контейнер имеет `restart: unless-stopped`; ручная остановка сохраняется. Входящие порты и публичный домен не нужны: используется long polling.

1. В Telegram создайте бота у **@BotFather** командой `/newbot`, получите токен.
2. Отключите Group Privacy: **@BotFather → /setprivacy → ваш бот → Disable**. Альтернатива — назначить бота администратором группы, чтобы он мог видеть обычные сообщения. После изменения privacy при необходимости удалите бота из группы и добавьте снова.
3. Добавьте бота в группу и разрешите отправлять сообщения.
4. Откройте терминал в папке `orange-telegram-bot`:

   ```sh
   cp .env.example .env
   ```

   В Windows PowerShell: `Copy-Item .env.example .env`.

5. Откройте `.env` редактором, задайте `BOT_TOKEN`. Цена по умолчанию — 110 ₽/кг; для ручного изменения задайте `ORANGE_PRICE_RUB_PER_KG`. Токен остаётся только в локальном `.env`, его не нужно вводить в чат с Codex или добавлять на GitHub.
6. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs -f --tail=50
   ```

7. Проверьте `/rate`: установленная вручную цена 110 ₽/кг доступна сразу после запуска.
8. Напишите в группе `Купил за 1000 рублей`: должен появиться один ответ в контексте исходного сообщения. Проверьте `/off` и `/on` администратором и обычным участником.

Остановка: `docker compose stop`; повторный запуск: `docker compose up -d`. Обновление после получения изменений: `docker compose up -d --build`. Не запускайте два экземпляра с одним токеном одновременно.

SQLite находится в volume `orange-data`: настройки чатов и ключи сообщений сохраняются после пересоздания контейнера. Не используйте `docker compose down -v`, если хотите сохранить эти данные. Резервную копию volume делайте при остановленном контейнере.

## Команды

| Команда           | Поведение                                                           |
| ----------------- | ------------------------------------------------------------------- |
| `/start`, `/help` | Назначение, форматы RUB, подключение к группе                       |
| `/rate`           | Установленная вручную цена за килограмм                             |
| `/status`         | Автоответы для текущего чата и установленная цена                   |
| `/on`, `/off`     | Настройки текущей группы; только администратор                      |
| `/refresh`        | Показывает установленную цену, как `/rate`; сетевого обновления нет |

Права проверяются через `getChatMember`. Бот обрабатывает новые `message.text` и подписи, игнорирует отредактированные сообщения, каналы, ботов, команды и служебные сообщения. По умолчанию группы включены. Без обозначения рубля или поддерживаемого денежного сленга ответа нет. URL и Telegram entities `code`, `pre`, `url`, `text_link`, `phone_number` исключены. Одинаковые суммы в разных местах сохраняются.

Автоматический ответ содержит только строки `🍊 300 ₽ -> 2,73 кг апельсинов`, без заголовка, источника, периода и служебного текста. Несколько сумм — один реплай с отдельной строкой для каждой, максимум пять строк; лишние суммы пропускаются без дополнительного сообщения. Установленная цена доступна через `/rate`.

## Цена и надёжность

Цена задаётся вручную через `ORANGE_PRICE_RUB_PER_KG` в `.env`, по умолчанию **110 ₽/кг**. Допускаются положительные дробные значения с точкой или запятой. Например, `110 рублей` → `🍊 110 ₽ -> 1 кг апельсинов`, `300 рублей` → `🍊 300 ₽ -> 2,73 кг апельсинов`.

Запросов к Росстату, скачивания XLSX, таймеров обновления и срока годности цены нет. Значение доступно сразу после запуска. Старый кеш цены в SQLite не используется; настройки чатов и ключи обработанных сообщений сохраняются. Для изменения цены поправьте `.env` и пересоздайте контейнер командой `docker compose up -d --force-recreate`. При изменении кода добавьте `--build`.

Исходящие сообщения идут последовательно по чатам: минимум секунда между попытками, максимум 15 автоматических ответов в минуту на группу. Очередь ограничена 30 сообщениями на чат и 1000 чатами; задания старше 30 секунд пропускаются. При отключении группы ожидающие автоответы тоже пропускаются. Telegram 429 повторяется максимум два раза с `retry_after`, в пределах срока задания. Удалённое исходное сообщение не приводит к ответу вне контекста (`allow_sending_without_reply=false`).

Ключ `chat_id + message_id` записывается в SQLite **до** отправки. После неоднозначного сетевого сбоя отправка не повторяется: Telegram `sendMessage` не предоставляет ключа идемпотентности, и повтор может создать второй ответ. Это гарантия «не больше одного ответа», с возможным пропуском при сбое. Ключи сохраняются 7 дней; более старые входящие сообщения в любом случае не обрабатываются. Временная потеря соединения polling обрабатывается grammY; ошибки отправки не останавливают бот. Сырой текст, пользовательские имена и токен не попадают в логи.

SIGINT/SIGTERM отменяет запросы Telegram, очереди и таймеры, завершает polling и закрывает SQLite.

## Без Docker и разработка

Нужен **Node.js 24 LTS**. В папке приложения:

```sh
npm ci
cp .env.example .env
# заполните BOT_TOKEN
npm run build
npm start
```

`npm run dev` собирает приложение и запускает исходники через tsx.

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

GitHub Actions `.github/workflows/orange-bot-ci.yml` проверяет приложение, скрипты доставки и Docker-образ. Постоянный процесс работает на вашем сервере или компьютере. Существующий deploy Dwar на GitHub Pages остаётся отдельным.

Проверки реализации: unit/integration тесты парсера, расчётов, ручной цены и Telegram; typecheck, lint и build. Интеграционные тесты подменяют транспорт Bot API, проверяя параметры ответов и права.
