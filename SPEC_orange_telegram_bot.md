# Техническое задание для Codex: Telegram-бот «Апельсиновый эквивалент»

## 1. Цель

Разработать Telegram-бота, который после добавления в групповой чат автоматически обнаруживает денежные суммы в российских рублях в новых текстовых сообщениях участников и отвечает **реплаем на исходное сообщение**, показывая эквивалент каждой суммы в **килограммах апельсинов**. Конвертация основана на последней доступной **официальной средней потребительской цене апельсинов в России (руб./кг)**, полученной из интернета. Бот не редактирует чужие сообщения и не пытается менять их отображение персонально.

**Важно:** реализовать рабочее приложение, а не прототип с фиктивными данными. Если доступ к источнику цены не удалось настроить, явно сообщить об этом в README и не заявлять, что интеграция готова.

## 2. Стек и поставка

- Node.js 24 LTS, TypeScript (strict mode).
- grammY для Telegram Bot API.
- SQLite для сохраняемых настроек чатов, кеша цены и ключей идемпотентности.
- `decimal.js` для денежной арифметики; `fetch` для HTTP; парсинг официальных HTML/XLSX/других машиночитаемых данных — выбранными поддерживаемыми библиотеками.
- `vitest` для unit/integration тестов; ESLint и форматтер.
- По умолчанию **long polling**, без публичного HTTP-порта; Dockerfile + docker-compose.yml с сохраняемым volume SQLite.
- `.env.example`, README.md, документ с описанием источника и структуры данных, npm-скрипты `dev`, `build`, `start`, `test`, `lint`, `typecheck`.
- Не использовать LLM для распознавания денег: правила и детерминированный парсер.

## 3. Поведение в Telegram

### 3.1. Обработка

- В группах и супергруппах обрабатывать новые `message.text`, а при наличии — `message.caption`.
- Игнорировать каналы, системные сообщения, сообщения самого бота и других ботов, команды, недопустимые или недоступные типы сообщений.
- Если в тексте нет явно обозначенной суммы в RUB — ничего не отправлять.
- Если есть 1–5 подходящих сумм — отправить **ровно один ответ** на всё сообщение с перечислением конвертаций; если сумм больше 5 — обработать первые 5 и указать, что остальные пропущены.
- Ответ всегда привязывать к `chat.id`, `message_id` исходного сообщения и `message_thread_id` при наличии (темы супергрупп). Использовать актуальный способ ответа в grammY / Bot API, предпочтительно `reply_parameters.message_id`; если исходное сообщение удалено — не отправлять ответ вне контекста.
- Если цена неизвестна — **не отправлять сообщение об ошибке в группу при каждом совпадении**. Сообщать о проблеме через `/rate` и логи.
- Настройка включения/отключения индивидуальна **для каждого группового чата**, а не для каждого участника; сам ответ виден всем участникам.
- По умолчанию после добавления бот активен в группе, при условии что имеет право видеть обычные сообщения и отправлять ответы.

### 3.2. Пример ответа

Входное сообщение:

> Купил монитор за 20 000 ₽, а клавиатуру за 3 500 рублей.

При **условной** цене 200 ₽/кг бот отвечает:

> 🍊 Апельсиновый эквивалент:
> 
> • 20 000 ₽ → 100 кг апельсинов
> • 3 500 ₽ → 17,5 кг апельсинов
> 
> Курс: 1 кг ≈ 200 ₽ · Росстат, [месяц год]

Это только демонстрационная цена: **200 ₽/кг не является реальным текущим курсом и не должна использоваться в production**. В настоящем ответе ставить подтверждённые цену и период наблюдения. Для официального источника формулировать «средняя цена», а не рыночный финансовый курс. Желательно прикреплять ссылку на опубликованный источник в `/rate`; в каждое автоматическое сообщение длинную ссылку добавлять необязательно.

## 4. Поиск рублёвых сумм

Парсер должен извлекать пары `исходный фрагмент / значение в рублях`. Поддержать:

- `500 ₽`, `500₽`, `500 руб`, `500 руб.`, `500 рублей`, `500 рубля`, `500 рубль`, `500 р.`;
- `1 500 ₽`, `1\u00a0500 ₽`, `1\u202f500 ₽`, `1500.50 руб.`, `1 500,50 руб.`;
- `2 тыс. рублей`, `1,5 тыс. ₽`, `3 млн рублей`, `1.2 млн ₽` (множители 1 000 и 1 000 000; считать строго через Decimal);
- разные регистры символов, одинарные и множественные пробелы, дефисный минус для отрицательных сумм (если возможно без ложных срабатываний).

**Не считать деньгами:** `1000` без валюты, `100 $`, `100 €`, `2026 г.`, URL, номера телефонов, повторные включения числа в одну и ту же сумму. `500р` можно распознавать, но не внутри слов. Игнорировать попадания внутри URL, `code`/`pre` Telegram-entities. В MVP распознавание `тыщ`, `к` без явно написанной валюты, диапазонов (`100–200 ₽`), приблизительных сумм словами и OCR не требуется.

Алгоритм:

1. Нормализовать Unicode пробелы и разделители без потери исходных диапазонов.
2. Извлечь кандидатов регулярными выражениями + валидацией границ слова/контекста.
3. Преобразовать в Decimal и применить суффикс масштаба.
4. Отсечь значения `NaN`, бесконечности, неоднозначные и значения по модулю более 1 трлн ₽.
5. Дедуплицировать только пересекающиеся совпадения, **не** удалять одинаковые суммы в разных местах сообщения.
6. Вернуть совпадения в порядке появления.

Правило для десятичных разделителей: запятая — десятичный разделитель; пробелы (включая NBSP и narrow NBSP) — разделители тысяч. Точку интерпретировать как десятичный разделитель для форм вида `1500.50`, а как разделитель групп тысяч — для формы `1.000` / `1.000.000`, если неоднозначность разрешается однозначным паттерном. Противоречивые форматы не конвертировать.

## 5. Цена апельсинов и интернет-источник (критично)

### 5.1. Первичный источник

**Росстат:** https://rosstat.gov.ru/statistics/price

Нужен показатель **«Средние потребительские цены (тарифы) на товары и услуги» / «Апельсины»**, география **«Российская Федерация»**, единица **рублей за 1 кг**, последнее доступное время наблюдения. Начать с раздела **«Средние потребительские цены на отдельные виды товаров и услуг по Российской Федерации, федеральным округам, субъектам Российской Федерации и обследуемым городам (в 2026 г.)»** либо эквивалентной витрины Росстата/ЕМИСС. Из таблицы нужно извлечь именно **абсолютную цену**, НЕ индекс потребительских цен в процентах и НЕ цену отдельного региона.

Не считать, что «еженедельная» таблица обязательно содержит апельсины; это следует проверить. Если апельсины есть только в месячной статистике — использовать месячную. Автоматически выбирать актуальный опубликованный период, а не фиксировать 2026 год в коде.

Создать интерфейс `PriceProvider` и реализацию `RosstatPriceProvider`:

```ts
interface OrangePrice {
  rubPerKg: Decimal;       // строго > 0
  observedPeriod: string;  // например, "2026-09", ISO для месяца
  publishedAt?: string;    // если опубликовано
  fetchedAt: string;       // ISO timestamp
  sourceName: 'Росстат';
  sourceUrl: string;        // конкретная проверяемая ссылка на источник
  geography: 'Российская Федерация';
  unit: 'RUB/kg';
}
```

Встраиваемый парсер обязан:
- получать актуальную ссылку на официальный набор/файл или пользоваться **реально проверенным** официальным API, если он существует;
- выбирать строку `Апельсины`, территорию `Российская Федерация` и самый новый период с фактическим значением;
- проверять структуру, единицу измерения, период и числовое значение;
- корректно извлекать данные из XLSX/HTML/JSON, если это фактический формат выбранного источника;
- отслеживать смену URL публикации, не привязываясь к единственному временному файлу;
- валидировать цену на положительность и разумный настраиваемый диапазон (например, 10–2 000 ₽/кг) и **не принимать ошибочно прочитанный процент как цену**;
- выбрасывать понятную ошибку, а не возвращать вымышленный курс.

Если официальные наборы позволяют достоверно извлечь данные только по месяцу — так и документировать. **Не суммировать и не усреднять цены регионов вручную:** методика официального среднего по РФ может отличаться от простой арифметической средней.

### 5.2. Кеш и сбои

- Хранить последнюю достоверную цену вместе с источником, территорией и датой наблюдения в SQLite.
- При старте пытаться обновить цену; затем проверять источник 1 раз в 24 часа. При успешном обновлении менять кеш только при подтверждённом корректном значении и периоде не старше уже сохранённого.
- При сбое повторить запрос с экспоненциальной задержкой и джиттером (ограниченное число попыток), не парализуя обработку Telegram-апдейтов.
- В течение 90 дней после `observedPeriod` разрешить пользоваться кешем при недоступном источнике, пометив старость в `/rate`. Если дата наблюдения старше 90 дней или цена никогда не была получена — автоответы не отправлять; `/rate` показывает диагностическое сообщение.
- В каждом ответе фиксировать именно `observedPeriod`, по которому посчитана стоимость. Не подменять дату наблюдения датой загрузки.
- `MAX_PRICE_AGE_DAYS`, период обновления, таймауты HTTP настраивать через env. Защита от одновременных фоновых обновлений (single flight).
- `MOCK_PRICE_RUB_PER_KG` разрешён исключительно в тестах и локальном dev-режиме с явной надписью о тестовом источнике; production не должен стартовать в mock-режиме.

### 5.3. Формула

`orangeKg = rubAmount / rubPerKg` с `Decimal`; расчёт — без промежуточных ошибок double. Вывод: >= 1 кг — до 2 десятичных знаков; < 1 кг — до 3–6 значащих десятичных знаков, чтобы небольшие ненулевые суммы не превращались в `0 кг`. Удалять лишние конечные нули, ставить десятичную запятую и пробелы между тысячами. Использовать обычное математическое округление для показа, без изменения фактического расчёта.

## 6. Команды и права

- `/start` (в личке) — кратко что делает бот, как добавить в группу и включить ему видимость сообщений.
- `/help` — справка и список поддерживаемых форматов.
- `/rate` — текущая цена: «1 кг апельсинов ≈ N ₽», период наблюдения, время загрузки, ссылка на Росстат, признак устаревшего кеша.
- `/on` — включить автоответы в данной группе (только администраторы группы).
- `/off` — выключить автоответы (только администраторы группы).
- `/status` — состояние для этого чата и наличие цены.
- `/refresh` — принудительная проверка источника (только администраторы группы; в личке только владелец из `OWNER_TELEGRAM_ID`; защита от частых вызовов).

Проверять права команд через Telegram API (`getChatMember`) и не доверять тексту о том, что пользователь администратор. При выдаче отказа по команде отвечать лаконично. Не позволять участникам группы менять параметры остальных чатов.

## 7. Антиспам, надёжность и приватность

- Обрабатывать апдейты идемпотентно: `chat_id + message_id` уникален; временная потеря соединения или повторная доставка апдейта не создаёт двух ответов.
- Максимум 1 автоматический ответ на исходное сообщение.
- Очередь исходящих сообщений **по чатам**; не превышать 1 ответ/сек и не более 15 автоматических ответов/мин на группу (с запасом к ограничениям Telegram); при перегрузке пропускать ответы старше 30 секунд, без накопления бесконечной очереди.
- Отдельно обрабатывать Telegram 429/`retry_after` и временные сетевые ошибки. Не повторять бесконечно.
- Ограничить размер входного текста, количество совпадений и длительность разбора, исключить катастрофический backtracking regex.
- Не логировать полный текст чужих сообщений. Логировать `chat_id`, `message_id`, число конвертаций, источник/период цены, ошибки без токена и персональных данных.
- Токен хранить только в переменной окружения, никогда в git/логах. SQLite и секреты в `.gitignore`, volume для Docker.
- Поддержать graceful shutdown и корректное завершение polling.
- Не отвечать на собственные ответы и не запускать циклы с другими ботами.

## 9. Обязательные тесты

### Парсер

- `Купил за 1000 рублей` → `[1000]`.
- `100 ₽ и 250 руб.` → `[100, 250]`.
- `1 500,50 руб.` → `[1500.50]`.
- `1,5 тыс. ₽` → `[1500]`.
- `2 млн рублей` → `[2000000]`.
- `500р` → `[500]`.
- `2026 г.`, `100 $`, `500` → `[]`.
- Две одинаковые суммы в разных частях сообщения → два совпадения.
- Emoji, Unicode NBSP, разрыв форматирования, длинный текст → корректность без исключений.

### Расчёт и ответы

- При тестовой цене 200 ₽/кг: `1000 ₽ → 5 кг`, `150 ₽ → 0,75 кг`, `1 ₽ → 0,005 кг`.
- Две суммы в сообщении → одно сообщение с двумя строками.
- Сообщение без RUB → нет ответа.
- В сообщении свыше пяти сумм → 5 расчётов и уведомление об ограничении.
- Уважать `/off`, права администратора, отсутствие цены, устаревшую цену, дубли апдейтов, режим темы форума, лимиты ответов.

### Источник цены

- Тесты на **реальных сохранённых фикстурах официального источника** с явно проверенными ожидаемыми периодом, территорией и ценой.
- Отдельные отрицательные фикстуры: только индекс в %, только региональная цена, отсутствуют апельсины, повреждённый файл, HTML со сменившейся структурой, будущая дата, цена 0.
- Интеграционный smoke test по **живому** источнику Росстата: опциональный для обычного CI, но **его нужно вручную выполнить во время реализации и зафиксировать результат**. Нельзя подменить live-проверку mock-данными и считать задачу завершённой.

## 11. Настройка Telegram (обязательно в README)

1. Создать бота у `@BotFather`, получить токен.
2. Отключить Group Privacy через `@BotFather` → `/setprivacy` → `Disable`, **или** дать боту статус администратора, позволяющий читать все сообщения группы. После изменения privacy mode, при необходимости удалить бота из группы и добавить снова.
3. Добавить бота в нужную группу; дать право отправлять сообщения.
4. Настроить `.env` и запустить `docker compose up -d --build`.
5. Проверить `/rate`: должна выводиться реальная цена с датой и ссылкой на источник.
6. Написать в группе `Купил за 1000 рублей` — должен появиться один реплай с кг апельсинов.
7. Проверить `/off`/`/on` с учётной записью администратора и обычного участника.

## 12. Критерии готовности

Работа считается завершённой, если:

- [ ] Бот автоматически работает в обычном групповом чате Telegram на любых официальных клиентах (Desktop, Android, iOS).
- [ ] Корректно распознаёт перечисленные варианты RUB и игнорирует нерелевантные числа.
- [ ] Публикует один ответ-реплай с вычислениями и периодом цены.
- [ ] Извлекает **реальную** официальную среднюю цену апельсинов **по РФ** из интернета и хранит её в кеше; есть проверенный успешный live-запрос.
- [ ] Не использует тестовую/вымышленную цену в production и корректно деградирует при ошибке источника.
- [ ] Администратор может включать/выключать автоответы для конкретной группы.
- [ ] Антиспам, ограничения Bot API, дедупликация и ошибки обработаны.
- [ ] Все unit-тесты проходят, сборка и typecheck успешны.
- [ ] Проект поднимается через Docker Compose и имеет понятный README.

## 13. Инструкция Codex о порядке работы

1. Создай минимальный работающий каркас бота и изолированный парсер валюты.
2. Исследуй **реальный** официальный источник Росстата: выбери наименее хрупкий пригодный формат данных, установи наличие поля `Апельсины`, территорию `Российская Федерация`, единицу `руб./кг` и действительный период. Не придумывай публичный API.
3. Реализуй поставщик цены и протестируй его на официальных фикстурах, затем live-проверкой. Если источник не удаётся прочитать — остановись с чётко описанной проблемой, без фейкового production fallback.
4. Реализуй кеширование, обработчики Telegram, команды, антиспам, тесты.
5. Запусти `npm test`, `npm run typecheck`, `npm run build`, `npm run lint` и, если доступен Docker, проверь compose.
